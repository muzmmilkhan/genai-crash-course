Anatomy of a Modern System

Every product, with or without AI, is assembled from the same set of base components. Learn the map first, then the tools for each part.

Why start with components

An AI model is rarely the whole product. Around it sits the same machinery that powers any application: somewhere to keep code, data, files and secrets, a way to know who the user is, and a way to see when things break.

Knowing these components lets you design a system, estimate effort, choose tools and talk to other engineers without guessing.

💡 Tip: You do not need to master every tool. You need to know what each component is for and have one sensible default for each.

The base components

ComponentWhat it doesExample tools
Version controlTracks code changes and enables collaborationGit, GitHub
DatabaseStores structured data and, for AI, embeddingsSupabase, NeonDB, MongoDB Atlas, Pinecone, ChromaDB
Caching layerServes repeated reads fast and cuts latencyRedis, Memcached
File storageHolds large files such as video, audio and documentsAWS S3, Azure Blob, Google Cloud Storage
NotificationsReaches users by email, SMS and pushSES, SNS, SendGrid, Twilio, Firebase, Exotel
AuthenticationProves who the user isAuth0, Firebase Auth, custom JWT/OAuth
Monitoring and loggingShows system health and explains failuresPrometheus, Grafana, ELK stack
SecurityProtects against abuse and attacksEncryption, rate limiting, firewalls
CDNDelivers content from servers close to the userCloudflare, AWS CloudFront
Environment managementKeeps configuration and secrets out of codeVault, AWS Parameter Store
PaymentsLets you charge for the productStripe, Razorpay

How the pieces fit together

A typical request flows through several of these components. Following one request makes the roles concrete.

  • The browser asks the CDN for the page and static assets.
  • The user logs in and the authentication service returns a token.
  • The API checks the token, applies rate limits, then looks in the cache.
  • On a cache miss it queries the database, and for an AI feature it also calls a model.
  • Uploaded files go to object storage, never into the database.
  • A notification is sent, and every step writes logs and metrics for monitoring.
Browser -> CDN -> API gateway (auth, rate limit)
                     |-> Cache (Redis) --miss--> Database
                     |-> Object storage (files)
                     |-> LLM / vector DB (AI features)
                     '-> Notifications, logs, metrics

Try it: pick a stack

Choose a type of product and see which components it needs first, with a sensible starter tool for each.

⚠️ Careful: Start with the smallest stack that works. Every extra component is something you must secure, monitor and pay for.

Key takeaways

  • Every system is built from a small set of reusable components.
  • AI features add models and vector databases, but not a different way of building.
  • Learn one default tool per component, then swap when a real need appears.
