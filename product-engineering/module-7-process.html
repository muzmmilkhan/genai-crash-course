From Idea to Deployment

Teams follow a repeatable process to turn an idea into a shipped product. Learn the documents, the stages and the order they come in.

The development lifecycle

Skipping early stages saves hours and costs weeks. Each stage reduces a different kind of risk.

Requirements: BRD and PRD

  • BRD: the business goal, target market, success metrics and constraints. Written for stakeholders.
  • PRD: user stories, features, acceptance criteria and priorities. Written for the team.
User story:
As a support agent, I want suggested answers drawn from our help docs,
so that I can reply faster.

Acceptance criteria:
- Suggestions appear within 3 seconds
- Each suggestion cites its source document
- Agent can accept, edit or dismiss
💡 Tip: Write measurable success criteria early, such as reduce average reply time by 30%. They also become your test for whether the AI feature is good enough.

Design: HLD and LLD

HLD is the map: services, data stores, external APIs and how data flows. LLD zooms into each piece.

  • HLD: a diagram of components, plus key choices such as SQL vs NoSQL and hosted vs self-run.
  • LLD: API endpoints and payloads, database tables, prompt templates, error handling.
  • Record important decisions and their reasons so they can be revisited.

Plan, sketch and build

  • Sprint planning: slice work into small pieces that ship in one to two weeks.
  • Wireframes: low-fidelity screens in Figma or on paper, tested with a few real users before coding.
  • Build the thinnest end-to-end slice first, then widen it.

Test, fix and deploy

  • Unit tests for logic, integration tests for services, and evaluation sets for AI outputs.
  • Fix defects in order of user impact, and add a test for each bug.
  • Deploy through CI/CD, with staging first, small rollouts and an easy rollback.
  • After launch, watch the monitoring dashboards and feed what you learn into the next sprint.
⚠️ Careful: A demo is not a product. Production needs auth, limits, monitoring, backups and a rollback plan.
