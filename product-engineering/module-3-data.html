Databases and Caching

Choose where your data lives. Compare relational, NoSQL and vector databases, then add a cache so repeated reads are fast.

Three kinds of database

TypeBest forHow data looks
SQL (relational)Structured data with relationships: users, orders, paymentsTables with rows and a fixed schema
NoSQL (document)Flexible or fast-changing shapes: content, events, profilesJSON-like documents
VectorSimilarity search over embeddings: RAG, recommendationsVectors of numbers plus metadata

Many products use more than one. A common AI setup is a SQL database for accounts and billing, plus a vector database for document search.

💡 Tip: If unsure, start with Postgres. It handles most needs, and extensions such as pgvector add vector search later.

SQL in one minute

CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  created_at TIMESTAMP DEFAULT now()
);

INSERT INTO users (email) VALUES ('a@example.com');
SELECT id, email FROM users WHERE created_at > now() - interval '7 days';
  • Add an index to columns you filter or join on often.
  • Use migrations so schema changes are versioned in Git.
  • Back up automatically and test that you can restore.

Vector databases for AI

A vector database stores embeddings, numbers that capture meaning. You embed the user's question, then fetch the stored chunks closest in meaning and hand them to the model. This is the retrieval step in RAG.

# conceptual flow
vector = embed("How do I reset my password?")
hits   = vector_db.query(vector, top_k=4)
answer = llm(question, context=hits)
⚠️ Careful: Keep the source text and an ID next to every vector so you can show citations and re-index when your embedding model changes.

Caching with Redis and Memcached

A cache keeps recent results in memory so the slow work (a database query or a model call) happens once. This lowers latency and cost.

ToolNotes
RedisIn-memory store with strings, lists, hashes, expiry and pub/sub. The common default.
MemcachedSimple, fast key-value cache. Fewer features, easy to run.
def get_profile(user_id):
    key = f"profile:{user_id}"
    cached = redis.get(key)
    if cached:
        return cached                 # cache hit
    data = db.fetch_profile(user_id)  # cache miss
    redis.set(key, data, ex=300)      # expire in 5 minutes
    return data
💡 Tip: This is the cache-aside pattern. Always set an expiry, and delete the key when the underlying data changes.
